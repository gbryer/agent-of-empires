<objective>
Fix three schema errors in the embedded sbx kit spec.yaml that cause `sbx kit validate` to fail on the live sbx CLI.

Purpose: The UAT revealed that spec.yaml was authored from documentation research with three incorrect assumptions: (1) `kind: agent` should be `kind: mixin` because the kit is used as a `--kit` overlay, not a standalone agent definition; (2) `commands.install[].command` must be a plain string, not a `["sh", "-c", "..."]` array; (3) `credentials.sources.ssh` must use `env: [SSH_AUTH_SOCK]`, not `agent: ssh-agent`. All three must be corrected, and the xtask linter, unit tests, and test fixtures must be updated to match.

Output: Corrected spec.yaml that passes `sbx kit validate`, updated linter, updated unit tests, updated fixtures.
</objective>

Apply three corrections to `src/containers/sbx_kit/spec.yaml`:

1. Change `kind: agent` to `kind: mixin` on line 2. Mixin kits are overlays applied via `--kit` on top of `sbx create <agent>`; they do not require an `agent.image` block. Agent kits define standalone agent definitions and require image config. Our kit is always used as an overlay.

2. Change `commands.install[].command` entries from array format to string format. Currently line 8 is `command: ["sh", "-c", "sh /sbx-kit/install.sh"]` and line 9 is `command: ["sh", "-c", "grep -qsE ..."]`. sbx parses install commands as shell strings (`cannot unmarshal !!seq into string`). Change to:
   - `command: "sh /sbx-kit/install.sh"`
   - `command: "grep -qsE '^\\.aoe-hooks/?$' \"${WORKDIR}/.gitignore\" || printf '\\n.aoe-hooks/\\n' >> \"${WORKDIR}/.gitignore\""`

   Note: `commands.startup` entries correctly use array format (`command: ["sh", "-c", "..."]`); do NOT change startup commands. Only install commands must be strings.

3. Replace the credentials block (lines 109-113). Remove the `[ASSUMED]` comment. Change from:
   ```
   credentials:
     sources:
       ssh:
         agent: ssh-agent
   ```
   to:
   ```
   credentials:
     sources:
       ssh:
         env:
           - SSH_AUTH_SOCK
   ```

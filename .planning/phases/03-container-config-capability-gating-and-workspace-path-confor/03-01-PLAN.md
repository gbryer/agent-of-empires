<objective>
Add capability-driven conformance to `build_container_config` so runtimes with `!supports_arbitrary_volume_paths` (sbx) receive a `ContainerConfig` whose every surviving `VolumeMount` and the `working_dir` satisfy `host_path == container_path`. Inconformable user-declared `extra_volumes` surface a typed `ContainerConfigError::InconformableExtraVolume`. Docker/Podman/AppleContainer paths produce byte-identical output to pre-Phase-3 (the post-pass early-returns when the capability is `true`).

Purpose: RT-04 ; `host_path == container_path` constraint enforced in `build_container_config` by capability-gated rewrite of both `working_dir` and every `VolumeMount.container_path`. Configurations that cannot be conformed surface a clear validation error before reaching the runtime.

Output:
- `ContainerConfigError` thiserror enum (1 variant: `InconformableExtraVolume`) inline at top of `container_config.rs` (per D-06 + RESEARCH; smallest-delta placement matching `RegistryError` analog).
- `pub(crate) fn conform_workspace_paths(volumes, working_dir, caps) -> (Vec<VolumeMount>, String)` shared helper (D-03).
- `fn conform_for_capabilities(config, caps, runtime_name, extra_volumes) -> anyhow::Result<ContainerConfig>` end-of-function post-pass (owned-passthrough per RESEARCH §Architecture Patterns Pattern 1; not the `&mut + mem::take` skeleton from CONTEXT D-02).
- Two new parameters on `build_container_config`: `capabilities: RuntimeCapabilities` (D-09) and `runtime_name: ContainerRuntimeName` (so the error variant interpolates the runtime per D-06).
- 9+ new in-module tests covering SC-1 (≥3 workspace shapes), SC-2 (Docker baseline-unchanged), SC-3 (typed-error downcast + companions), plus direct tests of `conform_workspace_paths`.

SC-3 ambiguity resolution: ROADMAP SC-3 mentions `volume_ignores` as the trigger; CONTEXT.md D-08 narrows it to user-declared `extra_volumes` only. CONTEXT.md D-08 is authoritative. `volume_ignores` and `extra_volumes` are distinct `SandboxConfig` fields. `volume_ignores` flows into `anonymous_volumes` (which Phase 3 clears silently per RESEARCH Open Question #3). Only `extra_volumes` carries the `host_path:container_path[:ro]` shape and is the sole trigger for `InconformableExtraVolume`. The SC-3 test asserts against the `extra_volumes` path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session layer -> sbx subprocess | publish_ports call passes port specs from ContainerConfig to sbx CLI; port specs come from user settings (validated upstream) |
| integration test -> real sbx binary | Test creates/destroys real sandboxes; #[ignore] gate prevents accidental execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 | Tampering | runtime.rs dispatch delegation | mitigate | All dispatch arms use .expect() with invariant message; panic on invalid state (sbx=None when kind=Sbx) rather than silent misbehavior |
| T-05-07 | Information Disclosure | publish_ports stderr logged via tracing::warn | mitigate | tracing::warn captures stderr for debugging; TUI renders only "port publish failed" message, not raw stderr (rendering is Phase 6) |
| T-05-08 | Denial of Service | integration test creates real sandboxes | accept | Tests are #[ignore]-gated and always call remove(force=true) in cleanup; risk is low (developer machine only) |
| T-05-09 | Elevation of Privilege | agent_name field on ContainerConfig | accept | Field is populated from self.tool (internal session state); not user-controlled input at this boundary; consumed only by kit::ensure which validates against known agent names |
</threat_model>

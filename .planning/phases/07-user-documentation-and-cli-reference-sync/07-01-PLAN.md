**## Overview** (1-2 paragraphs): Explain that Docker Sandboxes (sbx) provide microVM-based isolation via Docker Desktop. Each sandbox runs in its own microVM rather than sharing a kernel with the host. Mention this is an alternative to standard Docker containers for users wanting stronger isolation. Keep it brief per D-06.

**## Prerequisites** (numbered list):
1. Docker Desktop installed with sbx support (sbx ships with Docker Desktop).
2. Sign in: `sbx login` (opens browser-based Docker auth).
3. Set a default network policy: `sbx policy set-default <policy>`. Present all three options (allow-all, balanced, deny-all) with one-sentence descriptions each. Recommend balanced as a sensible default or allow-all for simplicity.
4. Store API secrets for each agent you plan to use. Include the secrets table per D-05, listing ONLY the clear 1:1 agent-to-service mappings: Claude Code/anthropic, Codex/openai, Gemini CLI/google, Hermes/mistral, droid/droid. Each row shows the `sbx secret set -g <service>` command. Add a brief note below the table that for multi-provider agents (OpenCode, Pi, Qwen Code, Kiro), users should set the secret for whichever provider they use; `sbx secret set` without arguments launches interactive mode.

**### Verify Installation** (discretion: include it, following Apple Containers pattern): Show `sbx version` and `sbx ls` commands with expected output guidance.

**## Configuration**: Show how to set `container_runtime = "sbx"` in config.toml. Include both the Linux path (~/.config/agent-of-empires/config.toml) and macOS path (~/.agent-of-empires/config.toml). Use the same toml snippet pattern as podman.md. Include a **### Profile-Specific Runtime** subsection showing how to scope sbx to a profile. Mention the TUI settings picker under Sandbox > Container Runtime.

**## Usage**: State that once configured, usage is identical to the Docker sandbox. Show the same `aoe add --sandbox .` and `aoe add --sandbox --sandbox-image` examples as peer guides. Note that in the TUI the Sandbox toggle uses whichever runtime is configured.

**## Important Notes** (per D-04, the sbx-specific "Key Differences" section):
- **Disk usage**: Each sbx sandbox is a full microVM with its own filesystem. Expect approximately ImageSize x ActiveSessions of host disk usage. Old sandboxes consume disk even when stopped. Remove sandboxes you no longer need with `aoe remove`.
- **Kit format (experimental)**: AoE ships an embedded sbx kit that configures each sandbox. The sbx kit format is experimental per Docker documentation; schema changes in future Docker Desktop updates may require an aoe update. Check for aoe updates if sandbox creation starts failing after a Docker Desktop upgrade.
- **Upgrade path** per D-08: sbx updates via Docker Desktop. To upgrade, update Docker Desktop through its normal update mechanism. Explicitly warn against `sbx reset` using a blockquote with bold Warning prefix (destroys all sandboxes, cached data, and secrets). Link to Docker's upgrade docs for details. Keep it brief.
- **No read-only volume mounts**: sbx does not support the :ro flag for volume mounts. If mount_ssh is enabled, AoE mounts SSH keys read-write.
- **No anonymous volumes**: sbx does not support anonymous volumes, so volume_ignores is not applicable.
- **Port publishing**: Ports are published after sandbox creation (not at create time). AoE handles this automatically; port-publish failures are surfaced as warnings without rolling back the sandbox.

**## Troubleshooting**:
- "Not logged in" / "sbx login": If AoE reports sbx as unavailable with a login error, run `sbx login` on the command line.
- "Policy not configured": Run `sbx policy set-default balanced` before creating sandboxes.
- Sandbox creation fails after Docker Desktop update: The sbx kit format may have changed. Check for an aoe update.
- Debug logging: Explain the AGENT_OF_EMPIRES_DEBUG=1 mechanism from AGENTS.md. Debug log location: ~/.config/agent-of-empires/debug.log (Linux), ~/.agent-of-empires/debug.log (macOS).

Style rules from AGENTS.md: No emdashes or -- as separators in prose; use commas, semicolons, or rephrase. No em-dashes.
